# EpiNu — Annotation Review (Claim 2 Human Ghost Audit)

A small static web app that lets Reviewer 1 and Reviewer 2 work through their
assigned images in the browser, records how long each image takes, and exports a
CSV in the same format as the existing `review.csv`.

The point of this app is **not** to change the study. It is a data-entry surface:
fewer transcription mistakes, and a review time that is measured rather than
estimated by hand.

## What this is

- A **static site** — plain HTML, CSS and vanilla JavaScript.
- **No backend, no database, no API, no login.** Nothing is uploaded anywhere.
- Answers live in the browser's `localStorage` until the reviewer downloads the CSV.
- All paths are relative, so it works from any subdirectory on GitHub Pages.

## Source of the reviewer package

The images and task lists are **copies** of the reviewer package generated by the
main research repository:

```
/Users/yutokohata/epinu-rfdetr-training/data/human_ghost_audit/reviewers/
├── reviewer1/{images/, review.csv}
├── reviewer2/{images/, review.csv}
├── assignment_manifest.csv     <- researcher-only, deliberately NOT copied here
└── review_instructions.md
```

- The source repository is **not modified** by this project.
- Images are byte-for-byte copies (verified by MD5), not regenerated. No model
  inference and no image rendering happens here.
- Task order is taken verbatim from each `review.csv`. The app never shuffles,
  re-samples or re-assigns anything.
- `assignment_manifest.csv` is **not** copied into this repository. Nothing
  served by this site records the original file name or which experimental
  condition an image belongs to.

## Running it locally

The app fetches `tasks.json`, so it needs to be served over HTTP — opening
`index.html` directly with `file://` will not work.

```bash
cd epinu-ghost-audit-review
python3 -m http.server 8000
# then open http://localhost:8000/
```

## Tests

```bash
node tests/core.test.js       # validation, CSV escaping, formatting
python3 tests/verify_package.py   # image MD5s, task IDs/order, no researcher-only data
```

`verify_package.py` compares against the source package; pass `--source <path>`
if it lives somewhere other than the default.

## How a review runs

1. The reviewer picks Reviewer 1 or Reviewer 2 (no password).
2. A brief screen shows the task count, the six target classes and the rules.
3. **Start Review** shows the first image and starts the timer.
4. For each image: `NO`, `YES` or `AMBIGUOUS`. `YES` requires at least one
   defect type, at least one affected target class, and a count of 1 or more.
5. **Next** saves the answer with its elapsed time and moves on. There is no way
   back — this is deliberate, so later images cannot change earlier answers.
6. After 53 images the completion screen offers **Download CSV**.

Timing details:

- The clock runs only while the reviewer is actually on the review screen.
- **Pause** stops it; paused time is excluded.
- Switching tabs or backgrounding the window pauses it automatically. It never
  restarts on its own — the reviewer has to press **Resume**.
- Opening the instructions from the review screen also pauses it.

Progress is written to `localStorage` after every image, under a separate key per
reviewer (`epinu-hga-review-v1:reviewer1` / `...:reviewer2`), so a reload or a
closed browser resumes where it left off. Downloading the CSV does not clear it —
the file can be downloaded again.

## CSV output

Filename: `reviewer1_review_completed.csv` / `reviewer2_review_completed.csv`.
Rows are in task order. UTF-8 with a BOM (so Excel opens it correctly), CRLF line
endings, RFC 4180 quoting.

Columns — identical to the existing `review.csv`:

| column | values |
|---|---|
| `task_id` | `HGA_XXXX` |
| `reviewer_id` | `reviewer1` / `reviewer2` |
| `defect_found` | `YES` / `NO` / `AMBIGUOUS` |
| `defect_types` | `;`-separated: `MISSING_LABEL`, `WRONG_CLASS`, `BBOX_ERROR`, `GRANULARITY_MISMATCH`, `SPURIOUS_LABEL`, `OTHER`, `NONE` |
| `target_classes_affected` | `;`-separated target class names |
| `number_of_defects` | integer |
| `notes` | free text |
| `review_time_seconds` | integer, measured automatically |

Conventions: `NO` is stored as `defect_types=NONE`, `number_of_defects=0`, with
no affected classes. `AMBIGUOUS` leaves the detail fields empty — the judgement
is in `defect_found`, with any explanation in `notes`.

Example:

```csv
task_id,reviewer_id,defect_found,defect_types,target_classes_affected,number_of_defects,notes,review_time_seconds
HGA_0001,reviewer1,NO,NONE,,0,,23
HGA_0002,reviewer1,YES,MISSING_LABEL;BBOX_ERROR,Tomato_Raw,2,"two tomatoes at the back, unlabelled",71
HGA_0003,reviewer1,AMBIGUOUS,,,,too blurry to call,44
```

## Live site

**https://digital-health-disparities-initiative.github.io/epinu-ghost-audit-review/**

This is the URL to give the reviewers. No login, no setup — they open it, pick
their reviewer ID and start.

Published from the `main` branch (root) of
`digital-health-disparities-initiative/epinu-ghost-audit-review`. Pushing to
`main` redeploys automatically; there is no build step, and `.nojekyll` makes
GitHub serve every file as-is.

**The site and repository are public.** Anyone with the URL can view all 106
review images. The page sends `noindex, nofollow`, which discourages but does not
guarantee exclusion from search engines. To take it down: **Settings → Pages →
Unpublish site**, or make the repository private.

## Reviewer instructions

The in-app **Review instructions** screen is the reviewer-facing copy, adapted
from `review_instructions.md` in the source package. It covers the six target
classes, the six defect types, and how to treat the two kinds of image —
including that model output is a hint, is not necessarily correct, that a
model/annotation disagreement is not by itself an annotation error, and that the
whole image must be checked rather than only the places the model pointed at.
